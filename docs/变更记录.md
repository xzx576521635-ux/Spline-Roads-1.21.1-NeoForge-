## 2. 稳定版本与回滚建议

> **2026-11-15 测试结论：v29 已通过用户测试（1/2/3 条全部正常），当时作为稳定基线。**
> **2026-11-16 更新：v56 已通过用户验证（标记/颜色/邻路清理、山区隧道删除均正常），取代 v29 成为当前稳定基线。**
> v29 基于 v16（无自适应坡道碰撞），并加入：
> - 禁止 clearance/air 把实体地形/基岩写成空气；
> - restore 缺失/空气 original 时恢复旧路 fill 材质，不再挖洞；
> - `FILL=NONE` 形状为空时整块碰撞兜底；
> - 按 mesh 补 deck。
>
> v29 不包含不可见标记清理；该功能已在 **v36** 单独加回并启用
> （删除/编辑道路后回收孤立 `road_marker`，见 v36 条目）。
> 道路尽头衔接仍是未完成需求，见 `待办与开发方向.md`。
>
> 如需更早的无 DH 修复版本，可回退 v12；无标记需求可回退 v9。
> v1~v3 是早期修复版；v4 是已知有严重视觉 bug 的版本。

## 3. 渲染机制问题（重点）

这一节记录最容易再次踩坑的渲染机制，后续改代码前务必先读。

### 3.1 VBO 与 terrain 双表示

Spline Roads 有两种路面渲染路径：

1. **VBO 路径（`RoadRenderer`）**
   - 路面、标线、路灯、护栏、树木等由 mod 自己生成几何并用 VBO 绘制；
   - 近处精度高，不受方块模型限制；
   - 远处超出原版渲染距离后不会绘制。

2. **terrain 路径（`RoadTerrainModels` + `RoadTerrainHandoff`）**
   - 把路面四边形发布到区块模型（`ModelData` 的 `QUADS/COVERS`），
     由区块渲染器绘制；
   - 主要用于光影/地形材质（Iris）和让道路进入区块渲染；
   - 通过 `RoadTerrainModels.active(section)` 隐藏对应 VBO 区间；
   - 地形模式关闭时必须清空 `snapshots/pending/published/parts`、
     dirty 受影响区块，并 bump `ownershipRevision`，否则 VBO 一直隐藏、道路消失
     （v2 修复的就是这个问题）。

**AUTO 行为：**
- 原始 v3 前：AUTO = 光影开启时 terrain，否则 VBO；
- v10 起：检测到 DH 时 AUTO 强制 VBO，避免 terrain 与 DH LOD 在渲染距离边界的
  黑噪点重叠带；手动 `/sr sf terrain` 仍可覆盖。
- 改动 AUTO 逻辑时，必须同时考虑：光影开关、DH 是否存在、VBO 区间隐藏状态、
  区块 dirty、DH LOD 重生成。

### 3.2 地形路面高度与 cover

- 道路实际方块是 `road_collision`/`road_infill`，顶面在道路表面；
- terrain 四边形的 Y 偏移是 `0.001/0.003`，**不要**改回 `0.05`（会浮空/侧缝）；
- `coverBelow`/`exposedFill` 把顶面四边形挂到下方方块顶面；偏移和阈值必须匹配；
- 地图/DH 取色时看到的“道路方块”其实是这些碰撞柱，不是路面四边形。

### 3.3 ModelData 与模型包装（最容易泄漏到世界渲染）

`RoadTerrainModels.wrap` 会把方块模型包成 `TerrainModel`。为了 Xaero/DH 取色，
曾让 `TerrainModel.getQuads` 在**没有 ModelData 时**返回沥青四边形：

- **错误做法**：只要 `asphalt` 就返回沥青；
- 后果：Sodium/区块渲染器也会走无 ModelData 路径，导致世界内整个道路碰撞体
  （包括桥底、道路内部、树附近）被渲染成沥青片；v9 修复。
- **当前做法**：只有调用栈来自 `xaero.*` 或 `com.seibel.distanthorizons.*` 时
  才返回沥青；世界区块渲染使用原始模型。
- 以后如果新增地图/DH 兼容，**不要再全局修改方块模型**；优先使用：
  - 标记方块（当前方案 A）；
  - 独立 coremod/mixin；
  - 明确的调用方检测（当前 stack 方案是兼容折中）。

### 3.4 DH（Distant Horizons）LOD

DH 只从**真实方块状态**构建 LOD，无法直接看到 mod 的 VBO 几何、标线、路灯/树木。

- 道路碰撞块 light opacity=0，DH 会当透明跳过；需要通过
  `DhApiBlockStateWrapperCreatedEvent.setOpacity(16)` 标记为不透明；
- 颜色/纹理通过 `DhApiBlockColorOverrideEvent` / `DhApiBlockTextureOverrideEvent`；
- **只有顶层**应显示沥青/标线；下层/侧面/桥底如果也涂沥青，从下往上看会出现
  大片沥青片（v7/v8 问题），当前非顶层透明；
- DH **自定义 box 渲染**（v4）不可用：黑平面、粗大设施、灰色方块堆、突兀切换；
  不要再用 AABB 粗模替代真实方块；
- DH LOD 数据会写入 `DistantHorizons.sqlite`，改颜色/透明度/纹理后**必须重置**
  对应存档 DH 数据，否则旧石头/旧颜色一直存在；
- DH 与 terrain 模式在黑噪点边界会重叠，AUTO 在 DH 下用 VBO（v10）；
- DH 远景设施/标线用**标记方块**（v10/v11）实现，不要用 box。

### 3.5 Xaero 地图

Xaero 地图按方块取色：

- 默认 `block_colors=0`（纹理取色）：读取方块模型最大 UP 面纹理/粒子纹理；
- 也可能使用 MapColor；
- 纯几何的路面/标线/树木/设施对地图不可见；
- 当前用不可见标记方块（`splineroads:road_marker`）提供位置/颜色；
- 标记模型为空 + `particle` 纹理：Xaero 纹理取色走粒子图标，MapColor 走 kind；
- 修改标记颜色/纹理后需要重置 `xaero/world-map/<世界>` 缓存。

### 3.6 标记方块（方案 A）

- `road_marker` 无碰撞、无遮挡、空模型；
- `getCollisionShape` 只在 `EmptyBlockGetter` 探测（DH `isSolid`）返回实体形状；
  玩家/放置方块返回空，避免挡路/挡建造；
- 放置由服务端 `RoadMarkerBuilder` 按 tick 预算完成，只放空气位置；
- 树冠/绿化按顶层 footprint 每 1 格填充；竖直结构沿高度放；
- **v36 起启用清理**（见下），旧标记会随编辑/删除自动回收；
- 标记只对已加载区块放置，远处需要靠近/重进补齐；
- 标记会写入世界存档。

#### 标记清理（v36）

- 每次重建完成时，比较“上一轮有效标记集合”与“本轮”，只把**真正消失**的标记
  所在区块加入清理队列（`finishBuild`）；不再整网重扫；
- 清理只在 `!building`（重建完成）后按 `CLEAN_BUDGET_PER_TICK=32` 区块/tick 执行，
  只删除 `state.is(splineroads:road_marker)` 且不在有效集合里的方块；
- 每会话第一次重建额外扫描所有当前道路区块，并以玩家为中心做一次 12 区块半径扫描，
  清理历史干净化前遗留的标记；
- 玩家周围按 `CLEAN_RADIUS_CHUNKS=4`、每 `CLEAN_SWEEP_TICKS=1200`（60 秒）扫一次，
  用于兜底“上个会话删掉、但不在本次有效集合里”的残留；
- 未加载/被挡住的候选位置计入 `unresolved` 并视为有效，避免刚加载区块时误删好标记；
- 若本轮标记集被截断（`complete=false`）则**本轮不删任何东西**，防止误删；
- 限制：未被加载的区块无法清理，DH 远处粗模要等玩家靠近（区块加载）后才会消失；
  若 DH LOD 仍显示，按第 2 节回滚原则重置该世界的 `DistantHorizons.sqlite`。

### 3.7 Sodium / Iris / 光影

- **VBO 几何不参与 Iris 阴影贴图**：VBO 路面是独立客户端网格，只在主渲染通道绘制；
  Iris 的 shadow map 只包含**区块烘焙**几何（`RenderType.chunkBufferLayers`）。
  所以：
  - terrain 后端（`RoadTerrainModels` 发布到区块模型）→ 桥/坡能在下方投影；
  - VBO 后端 → 路面不投影，桥下阴影消失（用户 2026-11-15 测试确认）。
  这也是 AUTO 在光影开启时切 terrain 的原因之一。
  Iris 只在装了 Immersive Engineering 时通过 `MixinShadowRenderer`
  在阴影通道补发 `AFTER_BLOCK_ENTITIES`，且给的 modelView 是单位矩阵，
  不能直接用来画世界坐标几何；没有 IE 时阴影通道根本不发事件。
  如果以后要做 VBO 投影，只能 inject Iris `ShadowRenderer.renderShadows`。
- Sodium 区块调度由 `coremods/terrain_upload.js` 的 `sodium_schedule` 修复，
  **不能丢**；
- Iris 状态通过 `ShaderPackState` 反射读取；
- 当前 `RoadRenderer.shaderMode(false)` 是硬编码非扩展顶点格式；参考上游曾用
  `extendedVertices(shader)`。修改它可能影响光影下 VBO 路面/设施纹理，需单独测试；
- 光影开关会触发 terrain/VBO 切换，必须验证：
  - 关光影不消失；
  - 开光影不浮空；
  - DH 存在时无黑噪点；
  - 区块不重复/不丢失。

### 3.8 远处道路（DH 空档）与坡道碰撞

**远处道路 VBO 距离**
- `RoadRenderer.viewChunks()` 是统一的可视距离来源：
  - 无 DH：原版 `effectiveRenderDistance + 2`；
  - 有 DH：`max(原版+2, distantRoadChunks)`，默认 24 区块。
- `buildVisible`、`RoadBuildScope`、`Preparation.next`、渲染 section 循环、
  `terrainSourcesReady` 都必须使用同一个 `viewChunks()`，否则会出现“数据有了但不建/不画”。
- `regionUsable()` 允许 DH 空档内、没有已加载区块的 64×64 region 也上传 VBO；
  未加载位置的灯光用 `0x00F000F0`（全天空）占位，区块加载后由 `pollLight` 重传。
- 道路记录同步：普通 `Watch/UnWatch` 只覆盖原版视距；DH 空档需要
  `roadWideSync`（客户端 → 服务端，半径 `distantRoadChunks`）+ 服务端 `wideSync`
  按半径扫描 `index.inChunk`，复用 `road()` 的 `state.sent` 去重。
- `ClientRoads.distantRenderable()` 阻止 DH 空档内道路被 `cool()/suspend()`，
  否则会出现“走近才构建、之后永久保留”的现象。

**坡道碰撞**
- v18 使用 v16 的 `RoadCollisionShape.smoothTops()`：只在 `RoadIndex.shape()`（碰撞形状）里
  把顶面按 1/8 格向下取整；平路不变，坡道合并小台阶。
- v17 的 1/4、1/2 自适应台阶已撤回（会导致陡坡与清理逻辑一起出问题），
  后续若要再做，必须单独测试“走得上 + 不会误清方块”。

**clearance 清理的安全边界（v18 重要）**
- clearance 清理只能写入 **尚未在 `writes` 中规划** 的格子，
  否则会覆盖路面/人行道/air 目标。
- 只清理 `canBeReplaced()` 方块、树叶、原木；
  **绝不清理草方块/泥土/石头/基岩等实体地形**。
- 这是 v17 把路面和基岩清空的直接修复点。

**不可见标记（road_marker）生命周期**
- 标记是真实方块，DH/Xaero 通过它显示道路设施/树冠/标线；因此道路删除后必须同步删除，
  否则 DH LOD 会继续显示“粗模”。
- `RoadMarkerBuilder` 维护本轮 `valid` 位置集合：
  - 每次 contentRevision 变化重建全部标记；
  - 重建完成后用 `ChunkAccess.findBlocks`（先经 section 调色板 `maybeHas` 过滤）
    扫描相关 chunk，删除不在 `valid` 中的标记；
  - 扫描范围：旧标记 chunk + 当前道路 chunk + 玩家周围 8 chunk，每 100 tick 重新扫描玩家周围；
  - `unresolved` 记录未加载/被阻挡的候选位置，防止区块加载后误删。
- 建路时 `RoadClearing.validate` 把标记视为可清理；clearance 清理也会直接移除标记，
  避免“坐标什么都没有却报不可拆除方块”。

## 5. 构建方法（无 Gradle）

1. 把需要的 class 编译到 `S:\srpatch\classes`：
   - classpath = `compiledWithNeoForge_6d24f5c637928ef470a1f1087a67b276d58bb7e1_output.jar`
     （mojmap，NeoForge 21.1.248）
     + 原始/上一个 jar（提供其它 mod 类）
     + DH jar（只编译可选集成类时）
     + `.minecraft/libraries` 下全部 jar
   - `javac --release 21 -encoding UTF-8 -proc:none`
2. 以某个稳定 jar 为基准：
   `jar uf <目标.jar> -C S:\srpatch\classes <变更的 class 相对路径...>`
3. 校验：
   - `jar tf` 条目数
   - 与基准 jar 解包后逐文件 SHA-256 对比，只应有预期 class 变化
   - `coremods/terrain_upload.js` 哈希必须与 v1 相同
4. 注意：`jar uf` 无法删除旧 class；如果删除了内部类，必须从旧基准 jar 重建，避免残留。

反编译源码里存在反编译器产物（泛型迭代器复用、`(List)` 原始类型等），重新编译时
需要少量不影响运行语义的修正，见 `RoadTerrainModels/RoadTerrainHandoff`。

### v64 — `splineroads-2.0-varargfix.jar`（修复区块上传交接的反射崩溃）

所以是**偶发**的（这次在区块上传时崩）。

```java
invoke(backend.setJob, render, (Object)null);
```

2. **Xaero 地图车道标线/树木等自定义几何**

   - 或给 Xaero 写可选 coremod/mixin，在地图取色时查询 Spline Roads 数据。
3. **Xaero 树木颜色**
   若树木是原版方块，Xaero 应按原版纹理/MapColor 显示；若看到统一灰色，通常是
   因为那些位置实际是道路碰撞块（Spline Roads 结构是几何，没有对应树方块）。

## 11. 记录规范（每次构建必做）

1. 版本号 = 上一版 + 1（主 mod `vN`、附属 mod `qbN`），**禁止复用**。
2. 构建完成后先复制到 `mods_backup/<_jar 文件名>.vN`（或 `.qbN`），**绝不覆盖**旧备份；
   再把同一文件装到 `mods/`（`mods/` 里每个 mod 只保留一个 jar）。
3. 计算 SHA-256 并立即写入三处：
   - `spline_work/变更记录.md`：`### vN — ...` 小节（原因 / 改动 / hash）
     + 顶部“当前版本 / 上一版” + 版本表行；
   - `spline_work/快速建造-变更记录.md`：`## qbN — ...` 小节 + 抬头
     “当前版本 / 备份路径” + 版本表行；
   - `mods_backup/回滚说明.txt`：当前版本块 + 备份列表行。
4. 附属 mod 每个版本同时留源码备份：`splinequickbuild-src-<版本>.qbN.zip`
   （不含 `build/`、`.gradle/`、`libs/*.jar`）。
5. 收尾必须运行一致性检查：

```
python spline_work/records_check.py
```

全部 `[OK]` 且 `RESULT: all records consistent` 才算完成；
出现 `[FAIL]` 先修记录再继续。

检查内容：安装中的 jar 与文档 hash 是否一致；
每个 `.vN` / `.qbN` 备份是否存在且 hash 一致；
最近几个小节与版本表是否齐全；
`回滚说明.txt` 的当前版本是否与变更记录一致。
